# Rapport de session — faire grandir le récit sans perdre le fil — 2026-09-24 (3)

*Session sur le modèle ; troisième du jour sur les parcours, d'où le suffixe `-3`.*

## Demande

« Si c'est nécessaire, on peut découper en plusieurs histoires ; si le cours est trop
petit, une seule. Au début un cours est léger, donc une histoire, mais plus il évolue,
plus il faudra la changer. Il faut éviter la perte de fil : que l'histoire précédente soit
toujours contenue, et qu'après on passe à d'autres histoires. »

## Ce qui a été ajouté

**SPEC-MODELE §8.3, axiome A17 — le fil ne se perd pas [E].** `build.py` scelle dans
`courses/<code>/parcours/fil.yml` la suite de toutes les étapes du cours dans l'ordre de
lecture. Le validateur exige que la suite actuelle la contienne, dans le même ordre.
Permis : insérer, prolonger, ajouter un parcours, découper un parcours en parcours
consécutifs. Refusé : retirer une étape du récit, en réordonner deux. Une refonte voulue
se déclare dans `course.yml`, `refonte_du_recit`, datée et motivée ; l'erreur devient un
avertissement et le fil est scellé à nouveau.

**SPEC-MODELE §8.4** : combien de parcours (un seul pour un cours court ; découper quand
le cours pose plusieurs questions ou qu'un fil dépasse vingt étapes, avec un
avertissement du validateur au-delà) ; comment faire grandir le récit (prolonger, ouvrir,
insérer, découper, dans cet ordre de préférence ; le premier morceau d'un découpage garde
l'identifiant). **§6** : la garantie correspondante. **§7** : `refonte_du_recit`.
